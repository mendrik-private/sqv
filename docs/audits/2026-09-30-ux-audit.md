# sqview UX, rendering and navigation audit

Audit date: 2026-09-30. Revision: `c35dfd6` (v0.3.0). Read-only; no source changed.

Method: source review of `src/app`, `src/ui`, `src/grid`, `src/db`; the running release binary driven
through a pseudo-terminal (pyte, character-exact screens at 140×40, 120×34, 80×14, 60×14, 32×8) and a
Weston screenshot; `examples/chinook.db` for real data; a crafted database for hostile names and cell
text. Items marked **verified** were reproduced in the running app; the rest are code findings with
file:line evidence.

## Verdict

The architecture (message/update, virtual window, typed grid, popups) is sound, but the product is not yet
consistent or fully trustworthy on screen:

- two popups **crash** on short terminals, and database text can **inject terminal escape sequences**;
- the grid **misreports numbers** that overflow their column and trims header names;
- `?` inside any text popup **throws away the user's input**;
- tab switching discards the view, the tab bar hides the active tab once it overflows, and views cannot be
  opened at all;
- popups reimplement lists, inputs, scrollbars, hints and frames six to eight times each, which is the
  root cause of most inconsistencies below.

## P1 — enum-like colouring

Current rule (`app/mod.rs` `inferred_enumerated_values`): < 20 distinct non-null values among the first 50
rows, each ≤ 20 chars, distinct ≠ total rows; only `Text` values are coloured; colour = position in the
sorted sample.

- **False positives**: `Customer.Fax` (12 unique numbers + 47 NULLs), `Employee.Phone`, and nearly every
  short column of small tables — there is no repetition test.
- **Incomplete/unstable**: `Customer.Country` sees 18 of 24 countries; unseen values hash into the same 8
  hues and collide; one new sampled value shifts every later colour; sorting/sessions change colours.
- **Palette**: 8 real hues against a limit of 19; reuses semantic colours (accent = focus, red = error,
  pink/blue/purple = date/number/blob); contrast drops on selected rows.
- **Disagrees with the editor**, which uses a full `SELECT DISTINCT … LIMIT 101`.

Proposed: one bounded query per open over non-PK, non-temporal text columns
(`COUNT(*), COUNT(c), COUNT(DISTINCT c), MAX(LENGTH(c))` over `LIMIT 5000`); enum when distinct ≤ 16,
non-null ≥ 10, distinct/non-null ≤ 0.3, max length ≤ 24 and no UNIQUE index; fetch the value set with the
value-picker helper; assign colours by stable hash (FNV) with collision probing inside the set, from a
~12-hue palette that excludes accent/red/type colours; keep results across schema refreshes.

## P1 — shortcuts: documentation and display

- **Help is stale and incomplete**: lists the removed "Reset col widths" (`help.rs:224`), "Enter (sidebar)"
  twice, palette commands mixed into the key column under "Misc"; missing header-click sort, scrollbar
  drag, alphabet rail/letter jump, middle-click close, sidebar wheel and all popup-specific keys; the scroll
  indicator overlaps the last line and shows `1 / 1` when nothing scrolls; no wheel scrolling.
- **README** lacks Ctrl-F, Ctrl-A, Ctrl-C/y, Y, Shift-↑↓, 1–9/0, Tab, Ctrl-W, `?`, Ctrl-P, Ins/Del, header
  sort and sidebar keys.
- **Status bar**: mode badge always ` BROWSE ` (even in popups/edit); hints are clipped mid-token
  (**verified** `[ctrl-h] he`); no read-only badge; filter count in `red` (reads as error); preview uses
  `Color::Black` instead of the theme; sidebar hint says `[enter] open` on section headers.
- **Hint vocabulary differs per surface**: `[enter]` (status) vs `↵` (find, pickers) vs `Enter` (editor,
  filter, date); `esc cancel` vs `Esc close`; date picker says Shift-Tab where help says BackTab. The filter
  footer always shows `Space activate · Del remove` although they only work with the rule list focused;
  insert row has only a toast ("Alt-Enter commits"); the palette has no footer and shows no shortcuts next
  to commands; the confirm banner can cut off `[y/n]` (60-cell cap) and expires silently after 5 s.
- **Icons**: `📂 📁 🔑 🔗` are used even with `nerd_font = false` (`symbols.rs:92-96`); emoji width is
  terminal-dependent and breaks alignment where it is measured as 1.

## P2 — performance and scaling

- Every window fetch runs `COUNT(*)` over the (filtered) view, `LIMIT/OFFSET`, and row-identity PRAGMAs;
  unindexed sorts re-sort the table per fetch; scrollbar drags are not debounced (`app/mod.rs`
  `fetch_window_around_focus`, `db/mod.rs:330,342`). Cache the count per view, debounce drags, keyset
  pagination from adjacent edges, cache identity per table.
- Blocking DB work on the UI thread: `jump_to_rowid` (`ROW_NUMBER()` over the whole view), copy-as-JSON
  with all rows, delete-confirmation counts/rowid resolution. Move to `spawn_db`.
- Find: `compute_column_widths` runs twice per frame and clones every hit row (`search_results_table.rs:73-84,331-339`).
- Hidden limits: FK picker loads only the first **200** target rows and filters in memory (values beyond
  are unreachable); Find searches only the first **10 000** rows without saying so. Push filtering into SQL.
- Grid allocates several strings per cell per frame (type sniffing, `" ".repeat`); precompute per-column
  display flags.

## Recommended order

1. **Stabilise (P0)**: clamp popup rects + render-size tests; `sanitize_display`; numeric overflow marker;
   `?` handling; value-picker default. Small, local changes.
2. **Correct the grid (P1 content)**: header width, focus drawing, viewport re-check on open/resize,
   formatter (reals, ellipsis, control chars), width sampling, schema-refresh retention, enum algorithm.
3. **Extract components (P2)**: `PopupFrame`, `SelectableList`, `TextInput`, `HintBar`, `Scrollbar`,
   `StateView`, `CellFormatter` in `src/ui/widgets/`; migrate every popup. This fixes most scrolling,
   mouse, hint and consistency findings at once.
4. **Navigation & discoverability**: tab overflow + per-tab state + tab keys; key conflicts; regenerate help
   and README from one keymap table so they cannot drift again.
5. **Features**: views, row detail, schema view, go-to-row, then column controls and the SQL console.

## Resolution (implemented 2026-09-30)

Verified with `cargo fmt`, `cargo clippy --workspace --all-targets -D warnings`, 227 unit tests and
pseudo-terminal runs (chinook at 120×30, 32×8, 24×4; the hostile-name database at 100×20).

**P0**
1. Every popup draws through `widgets::frame::PopupFrame`, which clamps to the frame. A test renders the
   whole app with each of the 17 popups at 1×1, 20×3, 30×5, 40×10, 80×15 and 120×40.
2. `widgets::text::sanitize` (`\n`→`↵`, `\t`→`→`, other controls→`�`) at every display boundary: cells,
   sidebar, tab labels, titles, status bar, editors, pickers, result tables. The render test fails if a
   control character reaches the terminal buffer.
3. Numbers that do not fit show `#` fill, never a digit prefix; numeric widths use the sample maximum.
4. `?` types into text popups; elsewhere help stacks over the open popup and restores it on close.
   Ctrl-H is no longer bound.
5. The value picker selects the best match; "use typed value" comes last.

**P1 content (6–15)**: headers budget name + sort marker; focus is drawn inside the cell; the viewport is
re-checked on every render (`set_viewport_rows`); one `ColumnKind` classifier and `cell_text` formatter
(declared scale or shortest reals, ellipsis, sanitised text, epoch dates) shared by grid, record view,
result tables and editor routing; text widths use P80 without NULLs; schema refreshes keep widths, enum sets
and settings of surviving columns; the chevron has its own cell; spare width goes to columns that lack it.

**Enum colouring**: one bounded SQL scan per open (`db::enum_value_sets`: ≤ 16 distinct, ≥ 8 non-null,
distinct/non-null ≤ 0.3, length ≤ 24, no unique index); FNV-hashed slots with collision probing in a
10-hue palette without accent, red or type colours; kept across refreshes.

**Navigation (16–25)**: the tab bar scrolls to keep the active tab visible with `‹ ›` markers and one
layout for drawing and hit-testing; each tab keeps its grid (focus, scroll, selection, columns); sort,
filters, hidden/resized columns and the frozen column persist per table (`view_settings`); `]`/`[` and
Ctrl-PgDn/PgUp switch tabs; every popup handles wheel and clicks; Shift-wheel and horizontal wheel scroll
columns; the deletion prompt blocks the mouse; lists keep a stored offset with PgUp/PgDn/Home/End; the
filter rule list scrolls; inputs scroll horizontally; the letter jump needs a `'` prefix; sidebar `q` is
gone; Esc goes to the sidebar; Ctrl-B moves focus to the table when hiding the sidebar; Ctrl-G goes to a
row; Space toggles a row. `j` still follows links on foreign-key cells, now announced by a status hint.
Keyboard enhancement (disambiguated escape codes) is enabled where the terminal supports it.

**Shortcuts**: `src/keymap.rs` is the single list; the help popup and the README tables are generated from
it (a test fails when the README drifts). The status bar shows the real mode (EDIT, FILTER, SQL, …), a
READ-ONLY badge, context hints that drop whole hints instead of clipping, `j follow link` on links,
`Enter fold` on sidebar headers, insert-row keys while staging a row and `y`/`n` while confirming; the
filter count is no longer red; the preview uses theme colours and adds a relative age to dates. The
confirmation says when it expires. The palette lists each command's key. Icons have ASCII/Unicode
fallbacks (`▾ ▸ PK FK`) when `nerd_font = false`; the unused focus-corner symbols were removed.

**Component reuse**: `src/ui/widgets/` holds `PopupFrame`, `ListCursor`/`paint_row`, `TextInput`,
`render_hints`, `Scrollbar` (shared draw and drag geometry, used by grid, sidebar, editor and every
scrolling popup), `StateView`, `cell_text`/`fit_cell` and `ResultTable`; `SearchPanel` serves Find, the
foreign-key picker and global search. The sidebar keeps its panel-style selection (accent on raised
background) rather than the popup list style.

**Performance**: the row count is cached per view and only recounted when sort, filter or data change;
rows stay on screen while a refresh loads; prefetch stops at the table edges; jump-to-row, copying rows,
and delete confirmation run off the UI thread; Find and the foreign-key picker search in SQL over the
whole view (limits are shown). Scrollbar drags coalesce because only one window read runs at a time.
Not done: keyset pagination and caching row identity per table (one `pragma_table_list` query per read,
negligible next to the count it replaced).

**Features**: views open read-only; tabs keep their state and sort persists; record view (`v`) with link
following and a JSON tree viewer (`o`); schema/DDL, indexes and referencing keys (`i` in the sidebar, or
the palette); go to row (Ctrl-G); referencing rows (`r`) open the other table filtered, Backspace returns;
hide (`-`), narrow/widen (`<`/`>`), freeze and show hidden columns; export view or selection to a chosen
path; copy rows as JSON/CSV/SQL and copy a column; multi-column sort (`S`); SQL console (`:`) with
persistent history (writes refused in read-only mode); search across all tables; READ-ONLY badge, and
ToggleReadonly refuses when started with `--readonly`. A failed first load now shows the error instead of
an empty table.
